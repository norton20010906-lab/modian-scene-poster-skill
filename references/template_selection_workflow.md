# 内部版式库与四候选选择流程

版式库服务于 Agent 决策，不是面向用户的风格商城。每轮固定输出“3 个成熟模板 + 1 个探索稿”。

## 位置约定

- P1 / 1：左上，成熟模板。
- P2 / 2：右上，成熟模板。
- P3 / 3：左下，成熟模板。
- P4 / 4：右下，本轮新探索。

候选完成后必须把这个位置关系告诉用户，并请用户回复 1、2、3 或 4 放大。P4 若被明确认可，可另行晋升。

## P1～P3 的选择

1. 只从 `data/layout_templates.yaml` 中 `status: approved` 的记录选择。
2. 先按 `scene_asset` 与现有主视觉匹配，再按 `best_for` 与本轮表达目标匹配。
3. 在适配度接近时优先选择不同的信息结构、产品占比和场景裁切，避免三张只换颜色。
4. 字、卖点、型号、识别状态必须来自本轮内容；模板不能携带旧产品文案。
5. 已由 P4 晋升的模板与用户参考模板地位相同，可在未来轮换进入前三位。

## P4 的探索

P4 必须先提出一个新的版式假设，例如非对称标题轴、局部超大产品、模块化数据叙事或特殊场景窗口。它可以学习商业案例的层级、留白、比例和节奏，但不得复制他人 Logo、文案或受保护图形成品，也不得只是成熟模板的换色版本。

探索稿仍须遵守事实、产品一致性、产品可见度、中文本地排版和溢出检查。没有通过质量门槛的探索稿不能放入四宫格。

## 选择后的行为

1. 从 `candidate_manifest.json` 精确定位编号与文件。
2. 展示对应的 1080×1350 单张海报。
3. 只迭代被选中的候选，不无条件重跑四张。
4. 选择 P4 本身不修改模板库；只有用户明确说“加入模板库”或同义表达时才启动晋升流程。
